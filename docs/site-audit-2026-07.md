2026-07-02 実施。コードベース調査4本（コード健全性／UX機能完成度／品質・a11y・PWA／UI/UX批評）＋**実機確認**（Playwrightでモバイル幅390pxの全画面を実操作・スクリーンショットは `temp/` に保存）＋本番ビルド計測に基づく。

## 1. 戦略・目的（KPIとの整合性、価値提案の明確さ） — 評価 3/5

**根拠**: 「反射で使えるようにする練習エンジン」という価値提案は CONTEXT.md・ADR で明文化され、計測→弱点→ドリルの設計に一貫して落ちている（強み）。一方、KPI が定義されておらず、計測基盤もゼロのため「うまくいっているか」を判断する手段がない。

**問題点**
- アプリ内で戦略が自己矛盾: Home の目標カードは「度数とコードトーンが鍵」と言いながら（実機確認: アドリブ目標時）、その直下の「今日の練習」は常に音名当て固定（`App.tsx:349-357`）。アプリ自身の助言と日課が食い違う。
- 主CTAが2つ並列: 「コードトーン練習をはじめる」（目標カード）と「今日の15問をはじめる」（今日の練習）が同格の琥珀ボタンで並ぶ（実機確認）。「今日まずやるべき1つ」をアプリが断定できていない。
- 成功指標（継続日数分布・セッション完了率・弱点改善率など）を測る仕組みが皆無（gtag/plausible等の検索ヒット0）。

**改善案**
- 「今日の練習」を目標に連動させる（goal.id → デイリーの出題モード配分を変える。`handleStartDaily` に goal 参照を追加）。
- Home の主CTAを1本化: 目標カードのCTAを「今日の練習」に統合し、デイリーの中身を目標で変える。もう片方はテキストリンクに格下げ。
- 個人利用でもプライバシーに配慮した軽量計測（Cloudflare Web Analytics=Cookie無し）を入れ、「デイリー完了率」「7日継続率」だけでも見る。

**優先度: 高**（CTA一本化・目標連動は工数小で体験の芯が通る）

**要確認**: このアプリのKPIは何か（自分の上達? 公開して利用者獲得?）。memory 上「公開vs個人」が未決のまま。この決定で観点4/5/12の優先度が大きく変わる。

## 2. UX・情報設計（ナビゲーション、導線、フォーム） — 評価 2/5

**根拠**: 文脈導線（結果→ドリル、Stats→ドリル）は良い思想だが、同じ情報の多重表現と選択肢過多で情報アーキテクチャが飽和。実機でも迷いが再現できた。

**問題点（実機確認済み）**
- 進捗表現が重複: 3統計グリッド＋MasteryBar が Home と成績の両方に表示。しかも**同じラベルで数字が違う**（実機: Home「累計16問・31%・24.6s」vs 成績「32問・19%・25.8s」— 定義不一致 `HomePage.tsx:40-46` vs `StatsPage.tsx:44-50`）。ユーザーはどちらを信じればいいか分からない。
- 成績ページは8ブロック縦積みで「苦手」の表現が3重（ヒートマップ誤答／苦手TOP5／弱点診断）。
- 理論タブの8ピルが横スクロールで見切れる（実機: 「ボイシン」で切れて以降のオープン/ダイアトニック/アルペジオは存在に気づけない）。
- 練習開始の入口が12種類以上あるのに、2大入口「今日の練習」と「チャレンジ」の機能差（弱点優先 vs 純ランダム）が文言に出ていない。
- 「今日の練習」カード内に「次のレッスン→」が同居（実機確認）— 練習カードの中にレッスン導線というグルーピング崩れ。
- 弱点診断の「度数M2が弱い」に練習ボタンがない（実機確認: 3診断中2つだけ「練習→」あり）。

**改善案**
- Home=次の一手（streak＋主CTA1本＋学習マップ）、成績=詳細分析、に役割分離。数値サマリは成績のみに。
- 累計/正答率の定義を1つに統一（終了済みセッション基準を推奨）。
- 理論ピルを「学ぶ/指板マップ/スケール系/コード系」の4つに統合（詳細は brushup-todo.md P2）。
- 「今日の練習=弱点を狙い撃ち」「チャレンジ=全範囲から腕試し」の副題を各1行追加（コスト最小・効果大）。

**優先度: 高**（数字不一致の統一と副題追加は1週間以内で可能）

## 3. UI・デザイン（視覚的階層、一貫性、CTA） — 評価 3/5

**根拠**: ダーク・スタジオ系のトーン＆マナー（エボニー＋琥珀＋等幅数字）は一貫していて質が高い。ただし自ら定めた規律「アクセントは1ビュー1色」に反する箇所が体験の中心にある。

**問題点（実機確認済み）**
- 回答ボタン12個が虹色（`NOTE_COLORS`: 赤/橙/緑/青緑/青/紫…）。クイズ画面で最も面積が大きい要素が多色で、琥珀アクセントの規律を最も重要な画面で破っている。色は音名と恣意的な対応で、ユーザーにとって意味を持たない装飾ノイズ。正誤の緑/赤の信号も埋もれる。
- 主CTA競合: Home に同格の琥珀ボタン2つ（観点1と同件）。
- 練習タブのグループ見出し（基礎/コード/進行・実戦/耳）がボタン群と位置ズレして読みにくい（実機: 「コード」の見出しがトライアド/コードトーンの中間上に浮く）。
- 学習マップの数値「20% / 32.1s」にラベルがなく意味不明（実機）。全フェーズに「挑戦中」バッジが同時に付き、ステータスとして機能していない。
- 見出しの英語アイブロウ（HOME/LEARN/STATS/CHALLENGE）と日本語UIの混在。
- スコアボード4指標＋チャレンジ進捗ピルの二重カウンタ（実機確認）。

**改善案**
- 回答ボタンを surface 色＋白文字に統一し、選択時のみ琥珀。NOTE_COLORS は指板マップ等の「見る」画面に限定。
- 学習マップ数値に「正答率/平均」ラベルと目標値（例「目標90%・3s」）を併記、バッジは「未着手/挑戦中/クリア」の3状態に。
- アイブロウを日本語化 or 削除（タブ名と重複しているだけ）。

**優先度: 中**（回答ボタン単色化は低コストで画面の signal/noise が劇的に改善）

## 4. コンテンツ（質、独自性、E-E-A-T） — 評価 3/5

**根拠**: 21レッスンの段階設計（初級→上級、盤面実演→理解度チェック→練習導線）は独自性が高く、「読ませず身体化する」方針も一貫。ただし後半の実装が薄い。

**問題点**
- 盤面実演（demo）が8レッスンで欠落（notes/diatonic/ii-v-i/function/secondary-dominant/tritone-sub/reharmonize/modulation）。進行・和声系こそ実演が効くのにテキストのみ。
- 理解度チェックが全レッスン一律2問、回答も保存されない（`LessonsPage.tsx:29-67`）。
- レッスン→練習の着地は21中3本のみ。`tritone-sub` は link 自体なし。
- E-E-A-T: 制作者情報・About・参考文献が皆無。個人利用なら不要だが、公開するなら信頼性の根拠がゼロ。

**改善案**
- 進行系レッスンに `LessonFretboard`＋`playChord` の実演を追加（部品は既存）。
- triad→TriadBuilder、function→KeyFunctionQuiz の導線を接続（`handleLessonGoto` に2分岐追加するだけ）。
- 公開するなら About ページ（何のためのアプリか・作者・出典）を1枚。

**優先度: 中**（導線接続は数時間、demo追加は中長期）

## 5. SEO（テクニカル、キーワード、内部リンク） — 評価 2/5

**根拠**: SPA 1ページ構成で、meta は title/description のみ。OGP・canonical・構造化データ・サイトマップなし（`index.html` 確認、og: の検索ヒット0）。検索流入は現状ほぼ期待できない構造。

**問題点**
- OGP/Twitter Card なし → SNS共有時にプレビューが出ない（共有=唯一の拡散経路なのに）。
- canonical・JSON-LD（WebApplication/LearningResource）なし。
- 全コンテンツがJSレンダリング。レッスン21本という良質コンテンツが検索にインデックスされる形になっていない。

**改善案（公開方針が決まってから）**
- 最低限（即日）: og:title/og:description/og:image（app-icon から1200x630生成）/twitter:card を `index.html` に静的追加。
- 中期: レッスンをURL化（`/lessons/notes` 等のルーティング＋prerender or SSG）すれば「ギター 指板 覚え方」系のロングテールを取れる唯一の資産になる。

**優先度: 低〜中**（個人利用なら低。公開するならOGPだけは高＝1時間でできて共有体験が変わる）

**要確認**: 本番URL・カスタムドメインの有無、公開して流入を狙う意思。

## 6. パフォーマンス（Core Web Vitals、表示速度） — 評価 3/5

**根拠**: 本日 `npm run build` 実測: **JS 658KB（gzip 202KB）の単一チャンク**、Vite 自身が 500KB 超警告を出力。CSS 17.6KB は健全。PWA precache 689KB。2回目以降は SW キャッシュで高速なので体感は悪くないが、初回ロードとキャッシュ更新時に重い。

**問題点**
- code-splitting ゼロ（`React.lazy` 使用0件）。理論系7ページ・レッスン全文まで初回に読み込む。
- antd の実用途は Tabs/Segmented/Switch/ConfigProvider の4種のみで、依存の重さに見合わない。
- Google Fonts が `<link rel="stylesheet">` で render-blocking（`index.html:16-19`）。
- ランタイム: App.tsx 単一コンポーネント（useState 29個）で回答のたびに全体再レンダー。`React.memo` 使用0件。実用上は許容だが指板SVG（72マーカー再生成）はメモ化価値あり。

**改善案**
- 理論タブ配下＋レッスンを `React.lazy`＋`Suspense` で分割（半日、初回JSを推定半減）。
- `Segmented` を自前トグルに置換して antd 依存を縮小（すでにトグルUIのTailwindパターンはコード内に多数ある）。
- フォントに `media="print" onload` パターン or `display=swap`（既にswapなら preload 追加）。

**優先度: 中**（PWA常用なら体感は限定的。公開して新規流入を狙うなら高）

**要確認**: 本番URLでの実測（Lighthouse/CrUX）。ローカルからは Core Web Vitals のフィールドデータを確認できない。

## 7. アクセシビリティ（WCAG準拠） — 評価 2/5

**根拠**: reduced-motion・ズーム許可・touch-action・コントラスト（主要テキスト）は良好だが、**中核機能の指板タップが支援技術で操作不能**という致命点がある。

**問題点**
- 指板セルが `<g onClick>` のみ（`FretMarker.tsx:55-59`）: role/tabIndex/aria-label なし → キーボード・スクリーンリーダーで「音名→位置」モードが完全に操作不能（WCAG 2.1.1/4.1.2 違反）。
- `aria-live` 使用0件: 正誤フィードバック・800msの自動送りが通知されない。
- 指板セルの実効ヒット径約30px（44px推奨未満）＋弦間隔18pxで誤タップしやすい。
- 正誤が緑/赤の色のみ（✓/✗記号なし、WCAG 1.4.1）。
- 音名12色ボタンは色覚特性で判別困難な組（C赤/D橙、G青緑/Ab青）を含む（文字併記があるため致命ではない）。

**改善案**
- FretMarker に `role="button" tabIndex={0} aria-label="◯弦◯フレット" onKeyDown`（Enter/Space）を追加。1コンポーネント修正で全指板に波及。
- フィードバック領域に `role="status" aria-live="polite"`。
- 正誤表示に ✓/✗ を併記。ヒット領域 r を拡大（viewBox スケール込みで44px相当に）。

**優先度: 高**（FretMarker と aria-live は合計1日以内。WCAG A レベルの欠落解消）

**根拠**: safe-area・dvh・ピンチズーム許可・PWAインストール・回答ボタンの下部配置は行き届いている。ナビと横スクロールに構造的な弱点。

**優先度: 中〜高**（ボトムナビは毎回の操作コストに効く）

## 9. CRO（コンバージョン最適化） — 評価 2/5

**根拠**: このアプリの「コンバージョン」=毎日練習を始めて完了すること（習慣化）。その入口と動機付けに複数の摩擦がある。

**問題点（実機確認済み）**
- 初期セッションの統計が意欲を折る: 1問で終了しただけで「0% / 前回比 -100pp ▲13.5s（赤字）/ 中央値45.5s」が大きく表示される（実機）。成績の推移グラフも少数データで0%↔100%に乱高下、苦手TOP5はn=1で「誤答100%」断定。**最小試行数ガードがなく、序盤ほどノイズを事実として突きつける**。
- 連続日数が基本モード以外で加算されない（`recordPracticeDay` は `App.tsx:365` のみ）→ 習慣化ループの根幹バグ。
- 練習リマインダーなし（streak があるのに切れる前に呼び戻す手段がない）。
- 誤答フィードバックが800msで自動送り（実機で視認できず流れた）: 「学び」が発生する瞬間を最速で捨てている。反射モードでも誤答時だけは2秒以上 or タップで送りにすべき。
- 目標「skip」を選ぶと Home に推奨が何も出ない（`goal.ts:80-83`）。

**改善案**
- n<5 では前回比・中央値・TOP5を出さず「まず◯問解こう」と促す表示に置換（`ResultScreen`/`StatsPage` に n ガード追加）。
- `recordPracticeDay` を全モードの終了処理へ（quizType分離と同時に）。
- 誤答時のみ自動送り遅延を2800msに統一（音名系も度数系と同じに。`useQuiz.ts:180`）。
- PWA通知 or 単純に「前回から2日空いています」を Home に表示する軽量版から。

**優先度: 高**（nガードと誤答遅延は数時間で、初週の離脱要因を直接潰す）

## 10. 信頼性・セキュリティ — 評価 3/5

**根拠**: 静的サイト＋バックエンドなし＋秘密情報なしで攻撃面は小さい。Cloudflare Pages 配信。ただし「ユーザーデータの生存」と「障害時の復帰」に弱点。

**問題点**
- **データ消失リスクが最大の信頼性問題**: 全記録が localStorage のみ、エクスポート/インポートなし（確認済み: Blob/download 実装0件）。ブラウザデータ削除・機種変更で全喪失。にもかかわらず設定に「練習履歴を削除」ボタンだけがあり、実機でも無害な「スコアをリセット」と隣接配置。
- ErrorBoundary なし: レンダー例外で白画面、オフラインPWAでは復帰手段なし。
- セキュリティヘッダ未設定: `public/_headers` なし（確認済み）→ CSP/X-Content-Type-Options 等は Cloudflare デフォルト任せ。
- 未使用依存3件＋デッドUI層が supply-chain 面のノイズ（`@ant-design/icons` 等、import 0件）。

**改善案**
- JSONエクスポート/インポートを設定に追加（全 gft-* キーを1オブジェクトに固めてダウンロード。半日）。削除ボタンの直前に「先に書き出す」導線。
- ルート ErrorBoundary（「再読み込み」ボタン付きフォールバック1画面。1時間）。
- `public/_headers` に最低限の CSP・`X-Content-Type-Options: nosniff`・`Referrer-Policy` を追加（30分）。
- 未使用依存の削除（`npm rm` 3件＋ `components/ui/`・`utils/cn.ts` 削除）。

**優先度: 高（エクスポート・ErrorBoundary）／低（ヘッダ・依存整理）**

## 11. 技術・保守性（分析基盤、エラー処理） — 評価 2/5

**根拠**: データ層の設計思想（ADR・純関数・弱点エンジン）は良いが、成長を支える基盤（テスト・CI・計測・共通化）が全部ない。既にコピペ起因の実バグが複数発生している。

**問題点**
- テスト0件・testスクリプトなし・CI なし（`.github/workflows` 不存在を確認）。lint/build すら自動で回らない。
- 6クイズコンポーネントの大規模コピペ（約1,400行）→ 記録漏れ・基準ずれの実バグが既に発生（brushup-todo.md P0 参照）。
- 計測データの正確性バグ: quizType 'interval' 一本化による度数統計・前回比の相互汚染、Home/Stats の指標定義不一致（実機で数字の食い違いを確認）。
- エラー計測なし（Sentry等0件）: 本番で白画面が起きても知る術がない。
- 永続化はスキーマ検証なしの `JSON.parse as T`、マイグレーション基盤なし、`gft-sessions-v1` は無制限増大。

**改善案**
- GitHub Actions で `lint + tsc + build` を push 時に実行（30分）。
- vitest 導入し、P0バグ修正と同時に practiceStore/mastery/phases の純関数へ回帰テストを書く。
- 6クイズを `useTapQuiz` フック＋`QuizShell` へ共通化（quizType 分離と同時に実施）。

**優先度: 高**（P0バグ修正・CI・テストの順。詳細は brushup-todo.md）

## 12. 法令・規約対応 — 評価 3/5

**根拠**: Cookie なし・外部送信なし・アカウントなし・課金なしのため、現状の法的義務は最小限。ただし説明文書がゼロなので「配慮している」ことを示せない。

**問題点**
- プライバシーポリシー・利用規約なし（確認済み: 該当文言0件）。データは端末内 localStorage のみだが、その旨の説明もない。
- Google Fonts を CDN 直読みしており、アクセス時にユーザーIPがGoogleへ送信される（GDPR圏では論点になった構成。国内個人利用なら実害は低い）。
- 公開して広告/計測を入れる場合は、外部送信規律（電気通信事業法改正）・ポリシー整備が必要になる。

**改善案**
- 設定 or ヘルプに「データの扱い」1段落を追加:「練習記録はすべてこの端末内にのみ保存され、外部送信はありません」（30分。信頼の担保としてコスパ最高）。
- フォントをセルフホスト（`@fontsource/dm-mono` 等）に切替えると、IP送信論点の解消と render-blocking 解消（観点6）が同時に済む。
- 計測を入れる際は Cookie 不使用の Cloudflare Web Analytics を選べばバナー不要のまま。

**優先度: 低（現状）→ 公開時に中**
