# 「今日の15分」を決める練習コース（トライアドを演奏で使う）を足す

## 要約

指板トレーナーに「コース」を足す。1回は約15分で、「指板で構成音を確かめる → 表示を消して探す → 伴奏に合わせて切り替える → つまずいた位置をもう一度 → ループ練習で自分の曲に当てる」の5ステップを、この順番で案内する。
最初の検証版（MVP）は5回分で、題材は 1〜3弦の C・F・G・Am のトライアドと、その 2〜4弦への移し替え。
伴奏は指板トレーナーの中で鳴らし（ADR-0005、2026-11-01 に運営者が確定）、ループ練習には手を入れずリンクだけでつなぐ。
音声の自動採点と課金はやらない。確かめたいのは「本人が2回目、3回目を自分から始めるか」で、GA4 のイベントで測る。

## 目的と非目的

目的:

- 対象は「コードは弾けるが、度数やトライアドを演奏で使えない人」。押さえ方は知っていても、1〜3弦の小さな形でコードをつなぐことはできない人である。
- 「今日は何を、どの順番で弾くか」をアプリが決め、開いたらすぐ始められるようにする。
- 既存の2ツールの組み合わせで、本人が練習を続けられるかを確かめる。

非目的（MVP ではやらない）:

- マイクで音を拾って自動採点すること
- 課金・コース販売（ADR-0005 の「収益化」を参照。検証の後で判断する）
- ループ練習（guitar-player）への機能追加
- 英語版のコース画面（文言の英語キーはビルドの都合で足すが、`/fretboard/en/` からは導線を出さない）
- 6回目以降の題材（7th、他の弦セット、他のキー）

## コースの中身（第1〜5回）

フレットは「3弦-2弦-1弦」（第5回は「4弦-3弦-2弦」）の順に書く。弦番号はギターの呼び方（1弦＝一番細い弦）。実装では既存の弦 index（0＝6弦）へ変換する。
すべて 2026-11-01 に音の高さから計算して確かめた（構成音が R・3・5 の3種類ちょうどになり、3本の指の幅が3フレット以内のもの）。

| 回 | 題材 | 進行（各2小節） | 使う形（3弦-2弦-1弦） | この回で気づかせること |
|---|---|---|---|---|
| 1 | C と F を1〜3弦で | C → F をくり返す | 低: C 0-1-0 → F 2-1-1／中: C 5-5-3 → F 5-6-5／高: C 9-8-8 → F 10-10-8 | どの組でも C の音が同じ場所に残り、2本の指だけが動く（共通音） |
| 2 | C と G を1〜3弦で | C → G をくり返す | 中: C 5-5-3 → G 4-3-3／高: C 9-8-8 → G 7-8-7／上: C 12-13-12 → G 12-12-10 | 今度は G の音が残る。C から見て G は5度上、F は5度下で、どちらも C と1音を共有する |
| 3 | C・F・G をつなぐ | C → F → G → C | 3〜6フレット付近: C 5-5-3 → F 5-6-5 → G 4-3-3 → C 5-5-3 | ポジションを動かさずに3つのコードが弾ける |
| 4 | マイナーを足す | C → Am → F → G | 中: C 5-5-3 → Am 5-5-5 → F 5-6-5 → G 4-3-3 | C と Am は2音が同じで、1弦が G から A に上がるだけ。3度が半音下がるとマイナー（Am 5-5-5 の 3弦5F＝C が Am の3度） |
| 5 | 2〜4弦へ移す | C → F をくり返す | 4弦-3弦-2弦で 低: C 2-0-1 → F 3-2-1／中: C 5-5-5 → F 7-5-6／高: C 10-9-8 → F 10-10-10 | 同じ考え方が弦をずらしても使える。2弦をまたぐと形が1フレットずれる（3弦と2弦の間だけ長3度） |

各回の前提として、レッスン `degree`「度数（インターバル）」と `triad`「トライアド（3和音）」へのリンクを回の冒頭に出す（読まなくても始められる）。

## 1回の流れ（5ステップ、約15分）

| ステップ | 画面でやること | 答え方・記録 | 目安 |
|---|---|---|---|
| ① 確認 | その回の形を指板に表示する。各音に度数（R・3・5）を出し、共通音を琥珀で強調する。タップで和音が鳴る | 「見た」ボタンで完了 | 2分 |
| ② 隠して探す | 音名・度数のラベルを消した指板で、「1〜3弦・3〜6フレットで F の 3度」のように出題する。10問。答えた後に正解の形を一瞬だけ出す | 指板タップ。正誤と回答時間を `gft-attempts-v1` に記録（quizType `course-triad`） | 4分 |
| ③ 伴奏で切り替え | 1小節のカウントの後、コード音とクリックを BPM で鳴らす。現在の形を明るく、次の形を薄く表示する。ギターで実際に弾く。初期は BPM 60、2小節ごとに切り替え | 演奏後に「止まらず弾けた／途中で止まった」を選ぶ。止まった場合はどの切り替え（例: C→F 高）かを選ぶ。採点はしない | 5分 |
| ④ もう一度 | ②の誤答と、前回までのコース課題の誤答（直近のもの）から最大5問を出す。③で「止まった」切り替えは、BPM を1段下げてその組だけもう一度鳴らす | ②・③と同じ記録 | 3分 |
| ⑤ 自分の曲に当てる（任意） | 「好きな曲の伴奏を、ループ練習で A-B ループして、今日の形で合わせる」と案内し、ループ練習へのリンクを出す | リンクを押したら完了。押さなくても回は完了できる | 任意 |

②がタップ式なのは、MVP では音を拾わないため。押さえる位置を頭の中で引けるかは、タップの正誤と時間で測れる。ギターで弾けるかは③の自己申告で見る。

### ③の伴奏の作り

- 既存の `audio.ts`（Web Audio、三角波のシンセ）を使う。`playChord` を拍の時刻に予約し、クリックは短い高い音を別に作る。
- 拍の予約は「少し先の拍まで先に予約する」方式にする（`setTimeout` だけで鳴らすと拍がずれる）。拍の時刻の計算は純粋関数にして単体テストを書く。
- 音の ON/OFF 設定（`gft-sound-v1`）が OFF のときは③の前に「音が OFF です」と出して ON にできるようにする。
- BPM は 60・72・84 の3段。前回「止まらず弾けた」なら次の回の初期値を1段上げる。
- 先に予約した音は、停止・画面の移動・BPM の変更・音の OFF のときにすべて取り消す。いまの `audio.ts` は鳴らした音の発音源（`OscillatorNode` など）を保持しておらず、音を OFF にしても予約済みの音は止まらない。そのため③用に、予約した発音源を一覧で持って `stop()` できる仕組みを足す。

## 2つのツールのつなぎ方

| 方向 | URL | 渡すもの | 受け取り側の対応 |
|---|---|---|---|
| ハブ・読み物 → コース | `/fretboard/course/`、`/fretboard/course/?day=1` | 回の番号 | 指板トレーナーが pathname とクエリ `day` を読む（新規） |
| レッスン `triad` → コース | アプリ内の遷移（`handleLessonGoto` に `course` を足す） | 回の番号 | 同上 |
| コース ⑤ → ループ練習 | `/looper/?from=course&day=1` | なし（クエリは計測用） | ループ練習は改修しない。クエリは無視されるが、GA4 の page_view の page_location に残るので、移動を数えられる |

データの受け渡しは MVP ではしない。ループ練習の保存形式（`guitar-player.phrases.v1`）に指板トレーナーから書き込むと、同じドメインなので技術的には書けるが、ループ練習の保存データを壊すおそれがある。受け渡しが要るとわかったら、ループ練習側に読み込み口を作る別仕様にする。

### 入口ページの作り

- `/fretboard/ear-training/` と同じやり方で、`vite.config.ts` の入力に `course/index.html` を足す。App は pathname が `/course/` で終わるとき、コース画面で開く。
- 画面を移ると App が `replaceState` でパスを書き換える（`src/App.tsx:172-180`）。コース画面ではパスを `/fretboard/course/` に保つ。
- PWA: `vite.config.ts` は `navigateFallback: null` で、ディレクトリごとの HTML を precache して返す。`course/index.html` も `globPatterns` で precache に入るが、Workbox はクエリ付きの URL を precache と照合しない（既定で無視するのは `utm_` と `fbclid` だけ）。そのため `ignoreURLParametersMatching` に `day` と `from` を足し、`/fretboard/course/?day=3` をオフラインで開けるようにする。同じ箇所のコメント「4つの HTML」も直す。
- サイトマップには MVP の間は載せない（検索流入より、導線からの継続を見たいので）。

## 保存するデータ

localStorage `gft-course-v1`:

```ts
interface CourseStore {
  version: 1;
  days: Record<number, {        // 回の番号（1〜5）
    startedAt: number;          // 最初に始めた時刻（ms）
    completedAt?: number;       // ①〜④を終えた時刻
    hidden?: { correct: number; total: number };  // ②の結果
    switchBpm?: 60 | 72 | 84;   // ③で最後に使った BPM
    switchOk?: boolean;         // ③の自己申告
    stalls?: string[];          // 止まった切り替え（例 "C>F:high"）
    looperClicked?: boolean;    // ⑤
  }>;
}
```

- `gft-` で始まるので、既存のバックアップ書き出しに自動で含まれる。「練習履歴を削除」でも消す（`clearPracticeData` の対象に足す）。
- ②・④の回答は `gft-attempts-v1` に quizType `course-triad` で積む。`rootNote` にコードのルート、`degree` に R・3・5 のどれかを入れ、さらに課題の識別子 `courseKey`（例 `d1:F:high:3`＝第1回・F・高い形・3度）を足す。
- 成績・ホームの集計からコースの回答を除外する。弱点診断（`mistakeClinic.ts`）とヒートマップは音名認識だけを対象にしているので混ざらないが、`practiceStore.ts` の `getOverallStats` は全回答を集計している。`getAllAttempts()` を使う集計関数を洗い出し、`course-triad` を除く条件を足す。quizType の型を広げたときに、集計側の分岐が新しい値で壊れないかも確かめる。
- 「前回までの誤答」は `gft-attempts-v1` から quizType `course-triad` かつ不正解を新しい順に取り、`courseKey` が同じものを1件にまとめる関数で取る（新規、単体テストを書く）。弦・フレットだけでまとめると、同じ位置の「C の R」と「F の5度」が1件に潰れるため。直近2000件の上限で古いものは消えるが、コースの用途では足りる。

## 計測（GA4）

送信は小さな関数 `track(name, params)` を1つ作って通す。`window.gtag` が無いとき（測定 ID の無い手元ビルド）は何もしない。

| イベント | いつ | パラメータ |
|---|---|---|
| `course_view` | コースの入口を表示 | `entry`（`direct`・`home_card`・`lesson`・`hub`。`?from=` か遷移元で決める） |
| `course_day_start` | 回の①を表示 | `course_day`（1〜5）、`is_repeat`（その回を2度目以降なら true）、`gap`（直前の回を終えてからの日数の帯。`gft-course-v1` の `completedAt` から計算し、`same_day`・`1-7d`・`8d+`・`none`＝前の回を終えていない） |
| `course_step_complete` | ①〜⑤の各ステップを終えた | `course_day`、`course_step`（`confirm`・`hidden`・`switch`・`retry`・`looper`）、`result`（②は正答数の帯 `0-4`・`5-7`・`8-10`、③は `ok`・`stalled`）、`bpm`（③だけ） |
| `course_day_complete` | ①〜④を終えた | `course_day`、`days_completed`（それまでに終えた回の数） |
| `course_to_looper` | ⑤のリンクを押した | `course_day` |

- キーイベントには `course_day_complete` を登録する。
- `course_day`・`course_step`・`result`・`gap`・`days_completed` を GA4 のカスタムディメンション（イベント範囲）に登録する。登録しないと探索で条件に使えない。GA4 の管理画面の操作は運営者の確認を取ってから行う（AGENTS.md）。
- 個人を特定する値や、指板の位置の生データは送らない。

## 成功の測り方

検証で答えたい問いは「最初の回を終えた人が、自分から次の回を始めるか」。

| 指標 | 定義（GA4 の探索で作る） | 目安（仮） |
|---|---|---|
| 主指標: 日を改めて次の回へ進む率 | 第1回の `course_day_complete` を送った人のうち、第2回の `course_day_start` を `gap` = `1-7d` で送った人の割合。同じ日のうちに続けて第2回へ進んだ人（`gap` = `same_day`）は「その場の勢い」なので数えない。分母は、判定日の7日前までに第1回を終えた人に限る（終えたばかりの人は、まだ7日を観測できないため） | 30%以上 |
| 第1回の完走率 | 第1回の `course_day_start` の人数に対する `course_day_complete` の人数 | 50%以上 |
| 伴奏ステップの実施率 | `course_step_complete`（`switch`）の人数 ÷ `course_day_start` の人数 | 60%以上 |
| 5回完走 | `course_day_complete` で `days_completed` = 5 の人数 | 数を見るだけ |
| ループ練習への移動 | `course_to_looper` の人数と、`/looper/` の page_view のうち `from=course` を含むもの | 数を見るだけ |

- 判定日は公開から6週間後。その時点で第1回を始めた人が30人に満たない場合は、目安を当てはめず期間を延ばす。
- 同じ人を日をまたいで追えるのは、同じブラウザで Cookie が残っている間だけ。端末を変えた人は別人として数えられる。
- 公開前に、運営者が自分で第1〜5回を通す。手が止まった場所と、③の BPM が合っているかを記録し、数値を直してから公開する。
- 目安を下回った場合の次の手は、判定日に決める（例: ③の BPM を下げる、1回を10分に縮める、第1回の題材を変える）。課金の検討は、主指標が目安を超えてからにする。

## 競合との違い

一言で: **ブラウザで開いてすぐ、日本語の度数の言葉で「今日の15分」が決まっていて、探す→伴奏で切り替える→自分が間違えた位置をもう一度、が1つの流れになっている。**

| 競合（2026-11-01 確認） | 持っているもの | 違い |
|---|---|---|
| Guitar Triad Trainer: Chords（iOS） | トライアドの転回形、CAGED の重ね表示、12種以上の進行と自作ループ、BPM の自動送り、メトロノーム。無料＋月額 $0.99 または買い切り $9.99 [^triad] | 道具はそろっているが、何をどの順で練習するかは利用者が決める。日本語・Web 版は確認できなかった |

| Drop2: Jazz Guitar Ear Trainer（iOS） | 練習時間を入れると1日のワークアウトを組む。ストリーク・ヒートマップ・正答率の推移、週次レポート。Premium 月額 $8.99 [^drop2] | 日々の計画と進捗管理はある。対象はジャズのドロップ2ボイシングで、App Store の説明にトライアドの記載は無い。日本語・Web 版は確認できなかった |

## 受け入れ条件

- 第1〜5回の形のデータ（`src/data/course.ts`、新規）について、各形の3音が「そのコードの R・3・5 のちょうど3種類」になることを単体テストで確かめる。上の表のフレットと一致すること。
- 誤答の取り出し関数、拍の時刻の計算、`gft-course-v1` の読み書きに単体テストがある。
- `track()` は `window.gtag` が無くても例外を出さない（テスト）。
- `/fretboard/course/` と `/fretboard/course/?day=3` を直接開くと、それぞれ一覧と第3回が開く（ビルド後のプレビューで確認）。一度開いた後、オフラインで `/fretboard/course/?day=3` を再読み込みしても第3回が開く。
- ③の途中で停止・画面の移動・BPM の変更・音の OFF をすると、予約済みの音がそれ以上鳴らない。
- コースの回答をした後も、ホームの累計と成績ページの数値が変わらない。
- `course_day_start` の `gap` が、`completedAt` からの日数どおりに `same_day`・`1-7d`・`8d+`・`none` になる（単体テスト）。
- ③で BPM 60 のとき、クリックの間隔が 1000ms（±20ms）で鳴る（開発サーバーで `AudioContext.currentTime` を記録して確認）。
- 320px・390px・1440px でコース画面の横はみ出しが 0。
- 既存のテスト（52件）が全件通り、`npm run build` と `npm run lint`（エラー 0）が通る。
- 「練習履歴を削除」で `gft-course-v1` も消える。
- 公開は master への push（Workers Builds）。push の前に運営者の承認を取る。

## 実装の順番（案）

1. `src/data/course.ts`（回と形のデータ）とテスト
2. `gft-course-v1` の保存と誤答の取り出し
3. ①②の画面（指板のラベル非表示を `Fretboard` に足す）
4. ③の伴奏（拍の予約）と自己申告
5. ④、⑤のリンク、ホームのカード、レッスン `triad` の導線
6. 入口 `/fretboard/course/`、`track()` と5イベント
7. 運営者が第1〜5回を通して数値を直す → 承認を取って push → GA4 のカスタムディメンション登録
